基于 idea 池与 openpi 真实结构，设计一个可落地的家庭长程任务特性方案（RSI pipeline C4）。

Idea 池：
1. <来自 rsi/daily 论文卡片，优先短期强相关篇>
2. <...>

步骤：
1. 【硬性前置】读代码结构并写出"当前结构基线"：
   π0 / π0.5 模型结构（主干、action expert / flow matching、π0.5 的分层规划器接口）、
   数据管线（LeRobot 字段、采样逻辑、自定义数据转换方式）、训练目标与配置、推理与 LIBERO 评测口径。
   同时判断 idea 的技术路线：VLA/端到端、分层规划/TAMP、世界模型/MPC、RL/自改进、数据仿真、感知记忆、基础模型或安全评测。
2. 产出 3 个不同角度的候选方案，其中至少 1 个可以是 openpi 外部模块/外部基线方案，不得全部默认改 VLA。每个方案必须给出
   "论文方法 → 技术路线 → openpi 或外部模块 → 最小改动点 → 验证方式"的映射；可落到 openpi 的部分写到文件 / 函数 / 配置 / 数据字段级，
   不能直接落地的部分明确新增模块、接口和实验边界。
3. 自我评审每个方案：能否落在现有结构上、算力成本、对长程完成率与 subgoal 成功率的预期影响、风险与回退路径；
   再为每个方案提一个更优替代。
4. 收敛 1 个 top idea，输出最终方案：
   特性目标（一句话，绑定短期主线 1 或 2）/ 关联论文与 idea / openpi 落地映射（模块 / 文件级改动点 / 影响面）/
   预期收益与固定评测指标 / 验证计划（先小规模跑通再放大）/ 风险与回退方案。
5. 写入 rsi/plans/YYYY-MM-DD-<feature-slug>.md。

约束：必须绑定两条短期主线之一；能落到 openpi 的方案给真实模块级映射，暂不能落地的高价值路线给外部基线和接口设计；预期收益给可量化指标；禁止把所有问题都强行改写成 VLA 改造。
